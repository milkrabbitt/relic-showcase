# 架构与数据归属
iOS SwiftUI、微信小程序通过受保护服务访问业务。MiniMax保持既有模型基准，服务器负责人物生成、聊天结算与记忆；客户端不能自报可信用户身份。

| 数据 | 权威来源与规则 |
|---|---|
| 原小程序/原iOS资料 | 分别保留原存储，不因绑定自动搬迁 |
| 验证后新共享角色 | 同一业务后端保存角色、素材、消息、记忆和额度 |
| 身份 | Apple登录与小程序双方验证关联；不凭同名或手机号合并 |
| 权益 | 老用户每角色200次保留；新账户统一Token账本为关闭中的候选。服务端逻辑请求幂等，不按气泡或传输次数重复结算 |
| 资料和人工记忆 | 修订号检查，拒绝覆盖另一端已更新值 |
| 删除 | 所属账号校验、共享状态与请求账本共同阻止复活 |
| 微信机器人 | 独立授权和通道状态，不以资料中转代表收发 |

稳定HTTPS已部署在既有已付资源，独立进程/持久目录/反向代理；不依赖个人Mac或临时隧道。两个微信中转保留原鉴权与测试名单，新共享角色数据由同一Python服务负责。原微信独立业务仍保留原归属。当前已部署普通conversation记忆处理模式，旧隔离后台worker关闭；普通第二真实账号的记忆效果仍待验。主动与机器人调度保持关闭。部署恢复与完整真机业务分别验收。
